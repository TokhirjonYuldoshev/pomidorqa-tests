## Как читать

Для общего технического обзора:

1. `README.md` в корне;
2. стратегия тестирования;
3. карта тестового покрытия;
4. архитектура;
5. обязательные проверки;
6. порядок разбора сбоев.

Документ по собеседованию нужен только для объяснения уже реализованных решений и не является источником требований.

## Правила документации

- описывается только то, что реально находится в `main`;
- факт отделяется от предположения;
- названия технологий, команд, файлов и GitHub checks не переводятся произвольно;
- обычные русские формулировки предпочтительнее лишних англицизмов;
- при изменении архитектуры, обязательных проверок, подготовки данных или правил диагностики документация обновляется вместе с кодом;
- при добавлении, удалении или существенном переносе test suite обновляется `test-coverage.md`;
- `CODEX.md` и `REVIEW.md` синхронизируются с учебным курсом и не переписываются ради стилистики.
